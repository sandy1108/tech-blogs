## 写在前面：随时把想到的事情留下来

我平时会记录很多零碎内容：工作做到哪一步了、突然想到一个小工具、看到一部电影、遇到一件生活琐事，或者只是有一个还没有想清楚的念头。这些东西当时看起来都不大，但过几天之后，往往就想不起来了。

以前我总想着“等有空了再整理”。结果就是，要么没有记录，要么记录下来之后一直躺在收藏夹里。要解决这个问题，我认为最好的办法是，把记录的门槛降下来，想到什么先记什么，哪怕是几句口语化的语音转写，也不要求当场写成一篇完整日记。

现在这套流程依靠的是之前搭好的 Obsidian 知识库。不同设备上的记录最终都会同步到知识库，OpenClaw 每天早上再去检查新增内容，帮我整理成当天的精华日记，同时更新当月的待办追踪。

## 随手记录和正式日记分开存

记录的时候，可以把随手记录当成素材，正式日记当成整理结果。素材可以很乱，里面可以有语音识别错误、半句话、临时想法和还没有结论的事情；整理后的日记则需要让未来的自己一眼看懂：当天做了什么、哪些事情已经完成、还有什么需要继续跟进。

这两个阶段分开之后，记录就没有那么大的心理负担。随手记录不需要先判断它是不是“值得写进日记”，也不需要想好标题和分类。Obsidian本身就有日记功能，直接创建当日的日记笔记，还可以自动加载配置好的模板，然后在当日笔记里直接语音输入法说话就可以了。我用的语音输入法是微信输入法和豆包输入法。

原始日记和整理后的日记分为两个目录：如果后面发现 Agent 的整理有遗漏，我还能回到原始记录重新核对。

## OpenClaw 每天早上负责整理什么

我给 OpenClaw 配了一个每天早上执行的 Cron 定时任务。它会先检查原始记录目录，找出新增且还没有处理的内容，然后按照日期读取和归并。

它主要做几件事：把当天零散的日记内容整理成摘要，提取已经完成的工作，找出需要继续跟进的待办，再把比较有价值的想法单独留下来。生活记录、工作记录和灵感不一定要混成一段话，按主题分开以后，月底回看会更清楚。

任务提示词里最重要的部分，其实是约定处理边界，而不是写一大段华丽的说明。例如核心要求可以压缩成这样：

```text
检查新增且未处理的随手记录，按日期整理为精华日记。
保留事实，区分已完成、待跟进、灵感和不确定内容。
语音转写不确定时不要擅自补全，必要时保留原文并标记。
不要覆盖原始记录；整理完成后写入对应日期的日记，并回填处理状态。
根据整理后的日记更新当月待办追踪，但不要凭空新增任务。
```

当 Agent 整理完成的时候，可以在日记的 frontmatter 里记录一个状态，这样就方便 Agent 筛选未整理的笔记。我还为此创建了一个专门的 Bases 数据库文件，这样 Agent 就可以快速地通过数据库筛选需要整理的笔记，也可以快速地修改对应笔记 frontmatter 里的字段。我觉得数据库这个功能在这个需求里还是挺好用的。

## 一次“随手记录到精华日记”的过程

比如一天里，我可能先后记下几段内容：上午处理了一个项目问题，中午看到一部电影，下午想到一个小工具，晚上又记录了一件需要下周继续跟进的事情。它们的记录时间不同，表达方式也不一样，甚至可能来自不同设备。

第二天早上，OpenClaw 会先按日期把这些内容收集起来，再分成几类。已经完成的事情进入完成项，仍然需要行动的内容变成待办，暂时没有结论但以后可能有价值的内容归到灵感里，纯粹的生活记录则保留一个简短摘要。

整理结果不追求把每一句原话都留下来。它更像一份当天的索引，让我1分钟内知道这一天发生了什么。

语音转写是这里比较容易出错的地方。专有名词、项目名称和人名有时会被识别错，Agent 如果根据上下文强行“修正”，反而可能把原意改掉。所以我更倾向于让它保留不确定内容，等我看到之后再人工确认。但是Agent可以把这些有可能出错的点列出来，这样就不用全文筛查了，只需要看Agent发现的那些不确定的点，然后进行修改就好了（真的是助理了）。

## 月度待办追踪：把每天的记录串起来

每天整理日记只是第一步，我还会让Agent把日记里的待办继续汇总到当月的追踪文档中。

口语化的记录很难靠正则表达式或固定脚本准确拆出待办。同一句话里可能同时包含已经完成的部分、下一步计划和一个还没决定要不要做的想法。这里大语言模型的理解能力确实帮了很大的忙，它可以结合上下文判断这句话究竟是在汇报结果、提出计划，还是随口一提。

月度追踪不会简单地把所有待办堆在一起，而是尽量区分已完成、进行中、待跟进、暂缓和不确定事项。月底回头看时，我能看到一件事情是什么时候出现的，后来有没有推进，最后是完成了、放弃了，还是变成了另一个项目。

这种时间线对个人项目、学习计划和求职准备都挺有帮助。有些事情一天之内做不完，如果只看当天日记，很容易以为它已经消失了；月度追踪会把它重新拉回视线。

## 还要跟AI约定好整理边界

比如，可以把待办找出来，可以帮我归类，但一件事情是否继续、是否值得公开、是否应该从月度计划中移除，还是要由我自己判断。

比如，日记还涉及很多私人生活和工作信息。有些话我可能只是为了吐槽，或者当个情感树洞，不想被整理和记录在待办里。

## 我是怎么一步步把这件事交给 OpenClaw 的

这套流程并不是一开始就设计好的。我最初只是让 Agent 帮我整理一篇日记，看看它能不能理解这些零散记录。发现输出方向基本可用之后，我再逐步补充目录位置、日期判断、处理状态、待办分类和失败时的处理方式。

每遇到一次问题，我就把它变成下一次任务需要遵守的规则。比如原始记录不能覆盖、不能把推测写成事实、已经处理过的内容不要重复整理等等。

这也是我最近使用 AI Agent 的一个感受：先把重复工作交出去，再根据真实失败案例补充约束，通常比一开始设计一个面面俱到的自动化系统更容易落地。

当然了，规则如果写得不明确，有一些非常顶级的大模型可能也能把问题解决，或者把日记整理得很好。但是这种小问题没有必要使用顶级大模型，所以我们把规则梳理得越细，就越可以放心大胆地把这个工作交给便宜的模型，比如 Deepseek-V4-Flash 或者 GPT5.6-Luna，这些模型也完全能够胜任。

## 最终效果和我的使用感受

现在我想到什么就可以先记下来，不需要马上决定它属于工作、生活还是灵感。第二天早上打开知识库，通常已经能看到一份整理过的精华日记；到了月底，还能从月度追踪里回看这些事情的来龙去脉。

一个字，爽！
