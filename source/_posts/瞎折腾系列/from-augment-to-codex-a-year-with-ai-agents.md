去年这个时候，我写过一篇 [《AI 写代码各种工具使用经历记录》](https://sandy1108.github.io/tech-blogs/2025/07/19/%E7%9E%8E%E6%8A%98%E8%85%BE%E7%B3%BB%E5%88%97/experience-record-of-using-various-ai-code-tools/)。那时我刚用上 Augment，AI Agent 对我来说还是个挺新鲜的东西。

一转眼又过去一年，2026年了，AI 这一年卷得是真快。去年一直到年底，我主要还在用 Augment；冬天去滑雪，滑了一个雪季，然后回来继续开始做兼职公司的项目时候，发现 Codex 已经相当猛了。自己上手以后也觉得它确实聪明了不少，尤其最让我觉得有提升的是，Codex已经可以”说到做到“了，也就是说，不是像以前的Agent一样，偶尔有时候会犯浑，嘴上答应得挺好、落到代码里又是另一套了，而变成了一个很靠谱的编程伙伴了。

这一年也不只是 AI 编程工具在换代。OpenClaw 这种让 Agent 常驻在本地设备上的玩法也火了一波，连 Mac mini 都被大家重新盯上了。确实能感觉到，AI 已经开始从编辑器里往真实设备和日常工作流里应用了。

![iShot_2026-09-18_21.34.47.png](iShot_2026-09-18_21.34.47.png)

## 起点：Augment 让我真正理解了 Agent 的价值

在更早之前，我对 AI 编程的理解主要还是补全、问答和生成一段代码，俗称”面向注释编程“。而Augment 给我的第一个明显感受，是它不只会回答眼前的问题，而是在它的ContextEngine的加持下，先理解整个代码库，再尽量按现有项目的结构和风格做事。

这件事听起来很朴素，但对实际开发很重要。一个工具如果只会快速写出一段“看起来能跑”的代码，往往还得花很多时间把它接回项目；而能理解上下文、减少风格割裂和重复摸索，才更接近一个真正能协作的开发伙伴。那时候，我第一次感受到，这个Augment，”还真挺懂我“。

## 中间的试用期：国产AI遍地开花，面对屎山代码越来越心累

Augment 之后，我陆续白嫖过 阿里的Qoder、字节的Trae、腾讯的CodeBuddy 等国产 AI 编程工具，也用过 亚马逊的Kiro。

它们并不是完全不能用，有的免费额度很有吸引力，有的接入模型后准确度也不错。但实际用下来，我没有留下一个长期主力：有些完成任务时考虑不够周全，有些更像是“写得很快的实习生”，写出来屎山代码，还需要我花不少时间收尾和补坑。

Kiro 给我的印象相对不错，尤其是它可以白嫖Claude模型，效果确实给力一些，毕竟这个阶段，在Harness还不够完善的情况下，只能靠强力的Claude模型来补了。

## 2026年初：离谱的全民养虾

这事发展的还真是让我觉得离谱~

最早听说大概是2026年初，听说有个Clawdbot开源项目挺火，然后就是小心眼的Anthropic公司公开指责项目名字跟自己的产品ClaudeCode太相似了，提出反对。就这事闹出不少新闻，我也是因为这事关注到了这个项目，后来经过两次改名，作者将其更名为OpenClaw了，当时也没觉得咋滴，但是让我震惊的是，没过多久，突然就铺天盖地火起来了，先是看到前同事干项目经理的，竟然写了个公众号，详细分享了自己OpenClaw部署的技术分享，让我感慨项目经理都开始搞技术了，紧接着腾讯大手开始推进了，好家伙，短短俩月这项目直接破圈，腾讯大楼门口不懂技术的人们排队求人帮忙装龙虾，直接给我惊掉了下巴：非技术人也要玩开源项目了？更离谱的是，互联网上竟然开始炒作一人公司，龙虾团队了，唉，我真是服了，这项目距离这种成熟还差太远了吧？都在高潮什么啊。后来我才明白，贩卖焦虑的人都是卖课的，卖Macmini的二道贩子们，他们赚得盆满钵满，但是好多技术小白的真金白银投进去也是没收获到什么东西，可悲可叹。

## 算了，我也白嫖个免费虾

3月份左右，我也是滑雪到尾声了，时间充裕了，也在我的老Macmini里部署了一个，还别说，确实挺好玩，灵活度高，可控性强。但是Token烧不起啊，这时候真得感谢腾讯大善人，QClaw火速推出，每天送大量Token，可以免费用国内各种大模型，别管效果咋样了，学习一下是够用的了，而且重要的是，毕竟也是基于OpenClaw套壳的，作为技术党，直接给他扒开，里面的openclaw.json还有skills就被我接管了~免费token，学习OpenClaw，爽！

哦，后来还冒出来个Hermes，我喜欢称他赫尔墨斯，但是网友们总喜欢称他“爱马仕”，可能大家觉得神话故事人物名字不如奢侈品品牌名字响亮？不过我已经用习惯了OpenClaw了，Hermes我也就没有长久的使用，而且实际上后来两个项目也是互相借鉴，基本上趋于相同，OpenClaw明显属于略显臃肿但是大而全且灵活度高类型的，我觉得符合我的喜好。

## SKILL机制真是太方便！

说来惭愧，OpenAI和Anthropic推出SKILL机制的时候，我还真没仔细看（还在沉迷滑雪中）。而OpenClaw的搭建后，我正式接触了skill机制（再次感谢腾讯让我白嫖Token），马上感慨，这真的是一个超级超级重要的发明！其实也不算是发明吧，只能说是这一种引导Agent干活的规范，这使得之前人们天天搞的提示词工程已经逐渐成为历史，连MCP协议也都在我的常用工作流里甘拜下风，现如今MCP也就回归了它本身的初衷：只负责承载一些特殊用途的外部工具。

主要是Skill太好用了，我果断把之前凝练的各种各样的规则，工作流，开发规范全都总结为一个一个的skill，每个skill还有渐进式发现的描述，节约上下文。只不过很多模型还不太适应skill，有时候偷懒不去读skill的细节，不过后来逐渐的这些Harness和模型都对此进行了优化，让Skill更好用了。

## 哦对了，还有Harness

新名词层出不穷，一开始并不理解Harness，但是后来仔细一想，自己用的这些Augment，Kiro，Codex，他们看起来都是干一个事情：把顶级规则以及skill描述，组织成上下文，发送请求给大模型，然后处理大模型返回的数据，然后调用工具干活，然后重复上述劳动。所以大家都这么干的话，总得给个统称吧！嗯，理解了~这就是Harness！

## 现在的主力：OpenAI Codex

今年 5 月开始，我把主要精力转到 Codex 上，到现在已经连续使用了几个月。

它让我满意的地方，就是“说到做到”，他回复做完了的事情，通常就是真的做完了，大大降低了AI的幻觉，而且做事很细，尤其是对长任务执行方面，感觉已经超越了Augment的体验：读代码、查文件、改动、运行验证、继续迭代，这些动作可以围绕一个任务连续完成。对我来说，这比在编辑器里反复复制问题、粘贴答案，再自己补齐上下文顺手得多。

而我去年用AI沉淀下来的各种项目经验、开发规范和踩坑记录，也终于得到了回报。我可以快速凝练成SKILL，迅速让Codex理解了我的开发思路，光速成长为我的好徒弟了~

关于Token方面，一开始我使用各路中转站，用得最多的就是code.miaomiaocode.com，这一家中转站还真是不错，6块钱一天，100刀额度，还是挺能用的。再后来7月份那阵子，Codex的产品负责人Tibo总是重置额度，看的我心痒痒，正好我手头还有不少编码工作，开Plus！然后就是猛猛蹬，天天盼重置，香啊！用的最多的一个月是8月份，难任务用gpt-5.6-sol-medium，简单任务用gpt-5.6-luna-max，一个月蹬了60亿Tokens，事后总结了一下，1个月订阅费20刀，但是帮我一起完成了我过去3个月才能干完的工作，效率提升200%！

目前 Codex 是我最愿意长期使用的 AI 编程工具。不过这并不意味着它在所有场景都一定最好；但至少在我现在的开发节奏里，它的综合体验最舒服。后来我甚至让他帮我SSH远程管理我的另一台电脑，帮我迁移QClaw数据到OpenClaw，帮我优化配置，帮我解决电脑的问题，甚至它逐渐增加了ComputerUse和BrowserUse之后，控制电脑和控制浏览器也不在话下，真是一条龙服务了。

如果说之前用的”屎山“AI是一群初出茅庐的程序员，那Augment时代就是可以成为我的团队成员了，但是需要我的强力监督，而Codex则可以认为已经出师了，有很强的主观能动性，能够彻底贯彻我给他的各种开发准则和要求，遵守团队的技术规范和开发要求，是一名合格的编程伙伴了！

## 关于 Claude Code

当然，关于AI编码工具，还有一个绕不开的大佬，就是Anthropic公司的 ClaudeCode。

不过，我对它的态度很明确：拒绝，完全拒绝。

这倒不是说它能力不行。Claude 系列模型写代码一直很强，Claude Code 的Harness口碑也不错，网上有大量用户把它当作主力工具。只是等我3月份滑雪回来，准备在三四月份认真试试它的时候，Anthropic公司面向中国用户的账号和服务限制已经越来越多了，甚至还把中国列为威胁，可笑。一个开发工具如果需要我先操心地区、账号、付款和封号风险，甚至它的开发公司还会参与政治斗争的话，不好意思，你能力再强，我也很难放心把长期工作流交给它。

再加上后来OpenAI家的 Codex 越用越顺手，我也就彻底失去了继续折腾 Claude Code 的动力。工具终究是拿来干活的，不是请回来供着的。ClaudeCode已经不存在断崖式领先的情况了，感觉不至于跪着给它送订阅费。至少在我这里，Claude Code 已经被拉进黑名单，Codex 则成了目前唯一的主力。至于是不是“唯一真神”，先让我再猛蹬一阵子再说。

## 这一年最大的变化

回头看，这一年最大的变化，是使用 AI 的方式变了。

以前用 AI 写代码，更像是在调用一个很聪明的临时工：这里补一个方法，那里问一个报错，生成完还得自己搬回项目里。到了 Augment，我第一次觉得 Agent 可以成为团队新手成员；到了现在的 Codex，我已经会把一个完整任务交给它，让它自己读项目、找资料、修改、验证，再把结果交回来。

Skill 和 Harness 的成熟又把这件事往前推了一步。以前每次打开一个新对话，都要重新解释“我是谁、项目怎么做、哪些坑不能踩”；现在很多经验可以整理成 Skill，开发规范、工作流程和踩坑记录也可以长期积累。它逐渐的可以熟悉我的习惯，越来越像一个长期合作的伙伴。

当然，这不代表人可以什么都不管。Agent 能力越强，一次操作能够影响的范围也越大。需求要不要做、方案往哪个方向走、哪些数据不能碰、什么时候允许提交和发布、最后怎么验收，这些事情仍然需要我来决定。说白了，跟开车类似，现在方向盘还是得经常控制一下，纯自动驾驶的话，有些情况下出错的后果是担不起的。所以，看来大概率我们程序猿还不会马上失业🐶。

所以我感觉，现在写代码的时间确实少了，但花在描述需求、制定规则、判断方案和验收结果上的精力反而更多了。我的角色也从“亲手把每一行代码敲出来”，慢慢变成了产品经理、架构师、代码审查者和项目负责人混在一起。听起来活儿更多了，但架不住旁边这位徒弟干得快啊，最后整体效率还是高了太多。不过也确实是容易更累，我曾经在插件化开发的项目中，同时开5个会话，同时开发5个插件，效率确实高，但是随着每个会话都返回了结果等我看文档或者验收效果时，我人也要炸了，有种AI催着我干活的感觉，不好意思被卷到了😂。

## 未来展望

现在开源的 DeepSeek Harness 也来了，国产的 Qoder、Trae、腾讯 WorkBuddy、豆包之类的都在火速追赶（或者抄袭😂）。接下来大家竞争的应该也不只是“接入了哪个模型”，而是谁能把上下文、Skill、工具调用、长任务执行、权限控制和验证流程真正组织好，以及让Harness与外接工具的连接变得更流畅，甚至云端AI一体化工作环境应该也在路上了。

我更期待的，是以后换一个 Harness，不需要把积累下来的规则和经验全部推倒重来；今天给 Codex 用的 Skill，明天稍微调整一下，也能交给其他 Agent。模型和工具肯定会继续换，但自己的知识、工作流和项目经验应该留下来，也就是，业内能够形成相对比较统一的一系列机制和规范。不过，估计厂商可能并不希望如此，厂商们通常是巴不得给自己挖更深的护城河呢。呵呵。

短期内，我大概率还是会继续把 Codex 当作主力。毕竟刚培养出一个“出师”的徒弟，总不能马上又从头带新人。不过有新的开源项目和国产工具，我还是会继续白嫖、继续拆、继续折腾。说不定等明年再续写这篇文章的时候，主力工具又换了，或者 Codex 已经真的能带着一支 Agent 团队替我干活了。

继续用，继续记录，明年再来看看。
